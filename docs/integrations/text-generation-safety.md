# Text generation request safety — 2026-10-26

Text generation makes one application attempt. In the locked @google/genai 1.52.0 SDK, omitting retryOptions takes a direct, single-fetch path. Supplying retryOptions, even attempts=1, takes a wrapper that throws plain errors for HTTP failures before response parsing. That loses ApiError.status and made permission/quota errors look like generic provider outages. Removed the option and covered actual SDK HTTP transport behavior with mocked responses. This is version-dependent behavior; SDK upgrades must pass the transport tests. The earlier claim that the original SDK configuration defaulted to five attempts was incorrect: the retry wrapper defaults to five only when that options object is present.

Research, Director, timeline, rewrite, proposals, passage revision and chapter actions use this shared text adapter. No automatic application retry or SDK transport retry is made. retryable in an error means a later manual submission may be useful, not that it is submitted automatically.

HTTP 401/403, 429, 404, 400/422, 408/504 and other failures now retain a numeric providerStatus and have safe, actionable error classifications. Raw provider messages, response bodies and credentials are never returned. Network timeout and DNS/connectivity errors are classified separately. User cancellation returns CANCELLED; a deadline returns TIMED_OUT, including when abort happens during SDK fetch.

The SDK request timeout increased from 15 to 60 seconds, remaining within the server’s 65-second deadline, client’s 75-second wait and route’s 90-second duration. This fixes a timing mismatch for chapter generation, not a proven cause of the historic failed request. A timeout does not prove the provider did no work or incurred no charge; the author decides whether to submit again. No token-accounting, billing reconciliation or provider-enforced spend cap was added.

Actual SDK mocked transport tests cover 400, 401, 403, 404, 408, 422, 429, 500, 503, 504 and a successful JSON response; every request asserts one fetch and preserves the submitted notebook. Tests also cover secret-safe errors, network timeouts, DNS failures, before-request and in-flight cancellation/deadlines. Novel, passage and backend checks and production build passed.
